# 界面场景决策系统 - 实现方案

## 一、目标

给一张游戏活动截图，系统自动判断"当前是什么场景"，然后按预设规则执行对应操作。

**典型流程**：
```
截图 → 认场景 → 查规则 → 执行动作 → 等1秒 → 再截图 → ...循环
```

**例子**：
- 看到"打开淘宝"按钮 → 点击它
- 进入淘宝App → 按系统返回键
- 回到活动弹窗 → 点击"关闭"或"领取"
- 回到主界面 → 停止

### 3.1 场景定义（SCENES）

**说明**：用文字告诉模型每种场景长什么样。模型会拿当前截图和你写的描述对比，选出最匹配的一个。

**请修改**：增删场景、改场景名、改描述文字。描述要写你实际看到的界面特征（按钮文字、颜色、布局）。

```python
SCENES = {
    "taobao_guide": """
        界面上有弹窗，弹窗里有'打开淘宝'或'下载淘宝'按钮。
        可能有红包图标。判定关键词：打开淘宝、下载淘宝。
    """,
    "taobao_app": """
        淘宝App界面：顶部有搜索框，页面是商品列表或店铺，

    """,
    "reward_dialog": """

        可能有红包、礼物图标或倒计时。
    """,
    "main_screen": """
        游戏主界面，没有弹窗遮挡，能看到角色、地图或功能入口按钮。

}
```

### 3.2 动作表（ACTIONS）

**说明**：每个场景对应执行什么操作。模型只负责认场景，动作由这张表决定，改起来方便。

**动作类型**：
| type | 含义 | 是否需要 target |
|---|---|---|
| `click` | 点击界面元素 | 需要：填要点的按钮名称，模型会找坐标 |
| `back` | 按系统返回键 | 不需要 |
| `wait` | 等待 N 秒 | 用 `seconds` 指定 |
| `stop` | 流程结束 | 不需要 |

**请修改**：

```python
ACTIONS = {
    "taobao_guide":  {"type": "click",  "target": "打开淘宝按钮"},
    "taobao_app":    {"type": "back"},
    "reward_dialog": {"type": "click",  "target": "立即领取按钮"},
    "main_screen":   {"type": "stop"},
}
```

**例子**：如果遇到弹窗要关掉，加一行：
```python
"close_dialog": {"type": "click", "target": "关闭按钮"},
```

## 四、实现步骤

### 步骤 1：写脚本 `state_machine.py`
- 用 urllib 调 API（无需装任何依赖）
- 两个函数：`match_scene()` 认场景、`locate_target()` 找坐标
- 先只打印决策，不真执行

### 步骤 2：用 10 张验证图测试
- 输出每张图识别的场景 + 建议动作
- 你肉眼判断对不对

### 步骤 3：修正场景描述
- 识别错的图，改 SCENES 里的描述
- 直到 10 张图全部识别正确

### 步骤 4：接入执行（可选）
- **Android**：`adb shell input tap x y` / `adb shell input keyevent 4`
- **Windows**：`pyautogui.click(x, y)` / `pyautogui.hotkey('alt', 'left')`
- **手动模式**：只输出决策，你自己操作

### 步骤 5：循环运行
- 截图 → 决策 → 执行 → 等待 → 重复
- 加防死循环：同一场景连续出现 N 次就停
