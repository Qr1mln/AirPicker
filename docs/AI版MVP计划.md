# AirPicker AI 版 MVP 计划

> 目标：在 **不改变现有「框选取码 → 粘贴到 PyCharm」闭环** 的前提下，给 AirPicker 增加 AI 能力。
> 参考方案：`docs/场景决策方案.md`（截图 → 认场景 → 查规则 → 执行 → 循环）。

---

## 一、背景与定位

| 维度 | 说明 |
|---|---|
| 现有定位 | 从 Android 实时屏幕框选目标，生成 Airtest 代码复制到剪贴板；是「取码工具」，不是自动执行器 |
| AI 版目标 | 增加「描述即取码」（智能取码）与「场景自动巡航」（自动巡航）两种能力 |
| 设计原则 | AI 是增强层，复用已有的截图、坐标换算、回写表达式、剪贴板和设备操作能力；不推倒重来 |
| UI 原则 | 沿用已确认风格：黑色面板 `#1e1e1e` + 白色线性图标 + 悬停渐亮 / 按下缩放动画；刷新双弧箭头、设置八齿齿轮 + 中心圆孔保持不变 |

---

## 二、MVP 范围

| 阶段 | 内容 | 是否纳入 MVP |
|---|---|---|
| P0 | UI 壳：右侧 AI 工具面板 + 浮动工具栏 AI 按钮 + 两者联动 + 设置持久化 | ✅ 是 |
| P1 | 智能取码：输入目标描述 → VLM 找坐标 → 画面高亮 → 生成代码复制到剪贴板 | ✅ 是（核心） |
| P2 | 自动巡航：场景识别 + 动作表 + 循环执行 + 防死循环 | ❌ 否（界面预留，二期实现） |
| 不做 | OCR 文字识别、多模型切换、模型训练、云端部署、iOS 支持 | ❌ 否 |

MVP 交付后，AirPicker 的使用方式变成：

```text
方式一（原有）：框选 → 生成代码 → 粘贴
方式二（新增）：右侧面板输入「立即领取按钮」→ 点识别 → 画面高亮确认 → 代码已复制 → 粘贴
```

## 三、总体设计

### 3.1 界面布局

```text

│                                      │  └────────────────────┘ │
│           投屏画面                    │  ┌─ 目标描述 ─────────┐ │
│                                      │  │ [立即领取按钮____]  │ │
│        ┌──────────────┐              │  │ [识别]              │ │
```

### 3.2 浮动工具栏 AI 按钮

- **图标**：直接绘制白色字母「AI」（不使用图形符号、不用 emoji），沿用 `icons.py` 手绘风格；
- **位置**：分割线下那组，跟在「滑动」按钮之后；
- **样式**：黑色面板 + 白色字母，悬停渐亮、按下缩放动画，与其他按钮一致；
- **状态**：面板展开时图标常亮高亮，收起时恢复普通亮度。

### 3.3 联动规则

1. 点击工具栏 **AI 按钮** → 右侧面板展开，按钮高亮；
2. 点击面板右上角 **`«`** → 面板收起，按钮取消高亮；
3. 两个入口状态始终同步（通过 `visibilityChanged` 信号，避免状态漂移）；
4. 面板展开时窗口加宽约 340px，投屏画面按剩余空间等比缩放（按原图分辨率裁剪的既有机制不受影响）。

### 3.4 数据流

**P1 智能取码（MVP 核心）：**

```text
用户输入目标描述（如「立即领取按钮」）
  → 取当前帧 latest_bgr（设备原图分辨率 BGR）
  → cv2.imencode('.png') → base64
  → POST /v1/chat/completions（模型输出 JSON：{"x":540,"y":1200}）
  → 主线程绘制绿色高亮框（约 1.5 秒）
  → 按「坐标回写表达式」生成代码 → 写入剪贴板
  → 状态日志显示结果
```

**P2 自动巡航（预留接口，二期实现）：**

```text
当前帧 → match_scene() 匹配 SCENES → 查 ACTIONS → locate_target()/back/wait/stop
  → 执行 → 等待 → 下一帧；同一「场景+动作」连续 N 次触发停止
```

## 五、配置数据结构

`settings.json` 新增字段（示例）：

```json
{
  "toolbar": { "horizontal": false },
  "ai_panel_visible": false,
  "ai_mode": "smart_pick",
  "ai_api_url": "http://192.168.162.1:1234/v1/chat/completions",
  "ai_model": "ui-box-scorer-qwen2.5-vl-7b",
  "ai_timeout": 30,
  "ai_scenes": [
    { "name": "reward_dialog", "desc": "有立即领取/恭喜获得字样的活动弹窗", "action": "click:立即领取按钮" },
    { "name": "taobao_app", "desc": "淘宝商品页，底部有首页/购物车/我的淘宝", "action": "back" },
    { "name": "main_screen", "desc": "游戏主界面，无弹窗", "action": "stop" }
  ],
  "ai_loop_interval_ms": 1000,
  "ai_max_repeat": 3
}
```

- `ai_panel_visible`：面板默认收起，不打扰原有工作流；
- `ai_mode`：`smart_pick`（P1）/ `auto_cruise`（P2）；
- `ai_scenes`：P2 用的场景/动作表，P0 阶段先用示例数据占位，可在面板表格中编辑；
- 所有字段在 `settings.DEFAULTS` 中提供默认值，读取时做类型校验，损坏时回退默认。

## 六、阶段任务与验收

### P0：UI 壳

1. `icons.py` 加 `draw_ai`，画白色「AI」字母；
2. `IconButton` 加 `active` 属性与高亮绘制；
3. `FloatingToolbar` 加 AI 按钮、`set_ai_active()`，调整固定尺寸；
4. 新建 `ai_panel.py`，按布局图搭出五块 UI，控件先占位不接逻辑；
5. `MainWindow` 接入 `QDockWidget`，实现按钮 ↔ 面板联动；
6. `settings.py` 加 `ai_panel_visible` 读写，启动时按设置恢复面板状态；
7. 场景/动作表填入三条示例数据，支持表格编辑但不执行。

**验收：** 点 AI 按钮面板展开、按钮高亮；点 `«` 收起、按钮恢复；重启后面板状态保持；原有取码/截图/按键流程无回归。

### P1：智能取码

1. 新建 `decision/scene_api.py`，用 `urllib` 调 OpenAI 兼容接口；
2. 截图编码：整帧 BGR → `cv2.imencode('.png')` → base64（**不能**直接编码原始像素）；
3. 提示词要求模型返回纯 JSON `{"x":…,"y":…}`，解析失败时记录日志并提示；
4. **异步调用**：用 `QThread` 或 `QRunnable` 执行网络请求，避免阻塞 30 FPS 抓帧循环；请求期间识别按钮禁用并显示「识别中…」；
5. 主线程绘制绿色高亮框（复用截图提示的颜色语言），1.5 秒后清除；
6. 坐标按现有「坐标回写表达式」生成代码，调用 `template_store` 的复制逻辑写入剪贴板；
7. 状态日志记录坐标与耗时。

**验收：** 输入「立即领取按钮」能返回合理坐标；高亮框位置正确；生成代码格式与手动取点一致；识别期间投屏不卡顿；请求失败有明确提示且不崩溃。

### P2：自动巡航（二期，不在本次交付）

- 实现 `match_scene()` 场景分类与 `locate_target()` 目标定位；
- `decision_mixin.py` 用 `QTimer` 做循环调度，动作分发复用 `GestureMixin` / `DeviceKeyMixin`；
- 防死循环按「场景 + 动作」组合计数，`wait` 类动作不计入；
- 状态日志显示每轮场景、动作、耗时。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 模型 `ui-box-scorer-qwen2.5-vl-7b` 名为打分模型，场景分类效果未验证 | P1 只做坐标定位（更贴合模型能力）；P2 前用 10 张截图验证分类准确率再接入 |
| 7B 模型局域网推理延迟 1~3 秒 | 异步线程调用；按钮禁用防重复点击；超时时间可配置 |
| 坐标系不一致 | 统一使用设备原图像素（与 `snapshot()` 一致），返回坐标不换算 |
| 防死循环误杀等待场景 | 按「场景 + 动作」组合计数，`wait` 动作不计入连续次数 |
| API 服务非 7×24 可用 | 地址 / 模型 / 超时全部放在设置中可改；失败时只记日志，不影响原有取码功能 |
| 面板挤压画面导致误操作 | 折叠入口常驻；画面缩放不影响原图裁剪精度；工具栏始终浮于画面之上 |
